The big idea: juice

Game developers call it juice: when one event fires many layers of feedback at once — motion, particles, sound, UI — all saying the same thing. The logic of our pickup hasn't changed since Lesson 8: an Area2D, a body_entered signal, one if. What changes today is everything around that logic. Feedback is the game telling the player: I heard you, and it mattered. Polished games aren't polished because their logic is fancier — they're polished because every event answers back.

Tween

A node-less animator you create in code: create_tween(). You queue steps — "move this property to this value over this time" — and it runs them in order. You met one in Lesson 14's damage numbers; today they're everywhere.

set_loops()

Makes a tween repeat its whole sequence forever (or N times). Perfect for idle motion: bob down, bob up, repeat until the node dies.

transition & ease

The shape of motion. TRANS_SINE drifts like breathing; TRANS_BACK overshoots and settles, like something landing with weight. EASE_IN_OUT = gentle at both ends.

set_deferred()

"Change this property at the end of the current frame, not right now." Required when physics is mid-step — you'll see exactly where below.

Part A — make it beckon

Before the player ever touches it, the sword should look alive. In the scene, the pickup's Sprite2D floats at y = -14 over a little stone pedestal (a prop the forest generator places), with a Glint particle emitter twinkling above it. The bob is three lines in sword.gd:

GDScript · sword.gd
extends Area2D

## The sword pickup: rests on its pedestal with a gentle bob and a golden
## glint until the player walks in — then chime, burst, banner, equip.

@onready var sprite = $Sprite2D

func _ready():
    var t = create_tween().set_loops()
    t.tween_property(sprite, "position:y", -17.0, 1.1).set_trans(Tween.TRANS_SINE).set_ease(Tween.EASE_IN_OUT)
    t.tween_property(sprite, "position:y", -12.0, 1.1).set_trans(Tween.TRANS_SINE).set_ease(Tween.EASE_IN_OUT)
Two steps, looped. A tween runs its queue in order: drift up to −17 over 1.1s, then down to −12 over 1.1s — and set_loops() starts the pair again forever. Up and back is one breath; the loop is the breathing.
"position:y" — tween a sub-property. The :y path animates just the height, leaving x alone. Also: we animate the Sprite2D child, not the Area2D — the pickup zone stays still while the art floats. The hitbox shouldn't breathe.
TRANS_SINE + EASE_IN_OUT — linear motion looks mechanical; sine drift looks weightless. One method call is the difference.

Part B — the moment itself

Here's the upgraded body_entered — the Lesson 8 wire, carrying five payloads:

GDScript · sword.gd
func _on_body_entered(body):
    if body.is_in_group("player"):
        Sfx.play("pickup")                                          # 1 · sound
        body.equip_sword()                                          # 2 · the actual logic (L17)
        body.hud.show_banner("Rusty Sword equipped!")              # 3 · UI
        body.spawn_sparks(global_position + Vector2(0, -14), Color(1.0, 0.85, 0.4), 14)   # 4 · particles
        sprite.visible = false                                      # 5 · the world changes
        $Glint.emitting = false
        $CollisionShape2D.set_deferred("disabled", true)
        get_tree().create_timer(1.5).timeout.connect(queue_free)   # outlast the glint's 1.4s particles
One event, five answers. Chime (ears), equip (hands — the sword appears in Will's grip via Lesson 17's equip_sword()), banner (eyes, top of screen), gold burst (eyes, world), and the pickup itself disappearing. Each is one line. Together they're a moment.
Two helpers ride along: body.hud (the player keeps a HUD reference — @onready var hud = get_node("../../HUD") in player.gd) and body.spawn_sparks(at, color, count), the player's gold-burst helper that builds a one-shot CPUParticles2D from code. Both arrived in the overhaul; this arc is touring them piece by piece.
set_deferred("disabled", true) — the physics rule. body_entered fires during the physics step; flipping a collision shape off mid-step is forbidden (Godot will print an error). Deferred = "at the end of the frame, when physics is done." Any time you touch collision from inside a collision callback, defer it.
Why not queue_free() immediately, like Lesson 8? Lifetime, again (Lesson 27's lesson!). The glint particles already in the air live 1.4 seconds — so: hide the art now, disable the trigger now, and free the node 1.5 seconds later, after the last sparkle has finished. Vanishing instantly is logic; lingering politely is craft.

Part C — the banner: a UI toast

That show_banner() call lands in hud.gd — the script the overhaul attached to the HUD layer (new to the curriculum; its full tour comes later this arc). Today we read its best pattern, one you'll reuse forever — the toast: slide in, hold, fade out, and survive being called twice in a row:

GDScript · hud.gd
var _banner_tween: Tween

func show_banner(text):
    if _banner_tween:
        _banner_tween.kill()              # a new banner evicts the old one
    banner.text = text
    banner.visible = true
    banner.modulate.a = 0.0
    banner.position.y = 96
    _banner_tween = create_tween()
    _banner_tween.tween_property(banner, "modulate:a", 1.0, 0.25)
    _banner_tween.parallel().tween_property(banner, "position:y", 84.0, 0.3).set_trans(Tween.TRANS_BACK).set_ease(Tween.EASE_OUT)
    _banner_tween.tween_interval(2.2)
    _banner_tween.tween_property(banner, "modulate:a", 0.0, 0.6)
    _banner_tween.tween_callback(func(): banner.visible = false)
Kill before you re-run. Tweens you store in a variable can be cancelled. Without the kill(), banner #2 arriving mid-fade fights banner #1's tween over the same properties — flicker, half-alpha, chaos. Stored-tween-then-kill is the standard guard for any re-triggerable animation.
parallel() — fade and slide at once. Normal queue steps run one after another; parallel() says "this step runs alongside the previous one." Fade-in and the drop-into-place share the same quarter second.
tween_interval(2.2) — a step that does nothing but wait. Slide in (0.3s) → hold (2.2s) → fade (0.6s): the toast's whole life in one queue, no timers, no _process.

Part D — make it matter

A reward is only as big as the want before it. The overhaul added one small mechanic-adjacent rule: no sword, no attack — so the pickup is the moment combat unlocks, not just a sprite change:

GDScript · player.gd — start_auto_attack()
func start_auto_attack():
    if not has_sword:
        if no_weapon_cooldown == 0.0:
            no_weapon_cooldown = 2.5
            spawn_text_over(self, "No weapon!", Color.GRAY)
            hud.show_banner("Find the sword — follow the road north!")
        return
    if is_instance_valid(target) and swing_timer.is_stopped():
        swing()                 # immediate first hit
        swing_timer.start()     # then keep swinging on the tick
The cooldown is politeness. no_weapon_cooldown ticks down in _physics_process; without it, holding the attack key would re-fire the banner sixty times a second. Every player-triggered message needs a "don't repeat yourself" guard.
Failure gets feedback too. Notice it's the same two tools — floating text + banner — answering a denied action. Silence on failure reads as "the game is broken"; a clear "no, and here's why" reads as design.
