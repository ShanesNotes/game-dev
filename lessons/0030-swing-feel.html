Swing Feel: Weight, Impact & Frozen Time

The combat math has been right since Lesson 24 — but a swing is more than a dice roll. Today the blade arcs through baked frames, Will leans into the blow, the camera flinches, and a critical hit stops the world for a twentieth of a second. None of it changes a single number.

Press attack: Will lunges into the strike as the blade sweeps out and settles back, a white swoosh flashes along the cut, sparks fly on contact — and when a crit lands, time itself hiccups and the camera shakes. The hit feels heavy. The damage formula never changed.

The big idea: impact is a frame story

A hit, in code, is instant — one function call, damage applied. What makes it feel like impact is everything you wrap around that instant: motion into it (anticipation), an exclamation at it (contact), and motion out of it (recovery). Film editors have known this for a century; games add one trick film can't: briefly stopping time. Each layer below is a few lines. Stacked, they're the difference between "the wolf's number went down" and "I hit that wolf."

tween_method

Tweens don't only animate properties — tween_method(f, from, to, time) sweeps a value and calls your function with it every frame. Today it sweeps a frame index.

Engine.time_scale

A global speed dial for the whole game. 1.0 is normal, 0.05 is one-twentieth speed — physics, timers, animations, everything obeys it. (Almost everything — see the trap below.)

hit-stop

The oldest impact trick in action games: freeze (or near-freeze) the world for a few hundredths of a second at the moment of contact. Street Fighter has done it since the '90s. The brain reads the hiccup as force.

camera offset

A displacement layered on top of wherever the camera is. Shaking the offset never fights the camera's follow logic — position is "where am I," offset is "how rattled am I."

Part A — the swing becomes frames

Lesson 29 baked the rest pose into the art, warned that the swing still rotated live, and named the left-handed mirror debt. Today both are paid at once. First, two cast members join player.gd's @onready block — the camera you placed back in Lesson 6, and a new effect sprite:

In the Inspector: Visible off, Position (0, −2), Z Index 5 (so the flash rides above nearby world sprites), and Offset x = 18 — the swoosh hangs 18px out along its own angle, so rotating the sprite sweeps it around Will like a blade trail.

The pipeline now bakes four sword textures — rest plus three steps toward full extension — and the swing animates an index instead of an angle:

GDScript · player.gd
# The swing is pre-rotated in the art pipeline too — four frames from rest to
# full extension. Stepping textures keeps every texel on the pixel grid.
const SWING_FRAMES = [
    preload("res://assets/sword_held.png"),
    preload("res://assets/sword_swing_1.png"),
    preload("res://assets/sword_swing_2.png"),
    preload("res://assets/sword_swing_3.png"),
]
var _swing_tween: Tween
GDScript · player.gd
func swing_sword():
    # Animate an index, not an angle: each frame is pre-rotated in the art,
    # so the blade stays crisp mid-arc. flip_h mirrors the frames for free
    # when the sword is in the left hand.
    if _swing_tween:
        _swing_tween.kill()
    _swing_tween = create_tween()
    _swing_tween.tween_method(_set_swing_frame, 0.0, 3.0, 0.08)   # slash out
    _swing_tween.tween_method(_set_swing_frame, 3.0, 0.0, 0.12)   # and settle back to rest
    # white swoosh flashed along the cut, aimed at the target (15° steps keep it crisp)
    if is_instance_valid(target):
        slash_arc.rotation = snappedf((target.global_position - global_position).angle(), TAU / 24.0)
    slash_arc.visible = true
    slash_arc.modulate.a = 0.9
    slash_arc.scale = Vector2(0.6, 0.6)
    var s = create_tween()
    s.tween_property(slash_arc, "scale", Vector2(1.1, 1.1), 0.1)
    s.parallel().tween_property(slash_arc, "modulate:a", 0.0, 0.16)
    s.tween_callback(func(): slash_arc.visible = false)

func _set_swing_frame(i: float):
    sword.texture = SWING_FRAMES[clampi(roundi(i), 0, SWING_FRAMES.size() - 1)]
tween_method is new: it sweeps a number (0.0 → 3.0) and calls _set_swing_frame with every in-between value; rounding turns the sweep into clean steps. Same Tween, but the target is a function, not a property — the most flexible tool in the tween box.
Out fast, back slow. 0.08s to full extension, 0.12s to recover — attacks snap, recoveries settle. Reverse the two numbers and the swing feels like it's underwater. (This asymmetry is the single most copied rhythm in action-game animation.)
The kill guard is Lesson 28's toast trick again: a stored tween, killed before re-trigger, so spam-swinging never leaves the blade stuck mid-arc.
snappedf(angle, TAU / 24.0) — the swoosh sprite rotates live (it's a translucent effect, allowed to be soft), but snapping its angle to 15° steps keeps it from landing at arbitrary near-miss angles every swing.
◈ WHERE THE FRAMES COME FROM

Lesson 29's make_sword_held() grows a loop — four rotations, each from the clean source, never re-rotating an already-rotated frame (every resample costs pixel quality; always go back to the original):

Python · assets/gen_polish.py
def make_sword_held():
    im = Image.open('sword_clean.png').convert('RGBA')
    for angle, name in ((-25, 'sword_held.png'), (-47, 'sword_swing_1.png'),
                        (-69, 'sword_swing_2.png'), (-90, 'sword_swing_3.png')):
        rot = im.rotate(angle, resample=Image.NEAREST, expand=False)
        rot.save(name)
Mind the sign: PIL's positive angle is counter-clockwise; Godot's is clockwise. These −25…−90 rotations sweep the blade clockwise on screen — down toward the target, a proper chop. (Sharp eyes will notice the old live swing swept the other way, up over the shoulder. The bake didn't just crisp the pixels — it was the chance to point the arc at the victim.)
expand=False is load-bearing: every frame stays on the same 32×32 canvas, so swapping sword.texture mid-swing never moves or resizes the sprite — same canvas, same hand anchor from Lesson 29. Let PIL expand the canvas and the blade would jump each frame.
Lesson 29's rule, extended: rotation that never changes belongs in the art — and so does rotation that animates, if you can afford a frame per step.

Part B — the lunge: lean without moving

GDScript · player.gd
# Brief body lean into the strike (visual only — the body doesn't move).
func lunge_toward(point: Vector2):
    var dir = (point - global_position).normalized()
    var t = create_tween()
    t.tween_property(anim, "position", dir * 5.0, 0.07).set_trans(Tween.TRANS_CUBIC).set_ease(Tween.EASE_OUT)
    t.tween_property(anim, "position", Vector2.ZERO, 0.14)
It animates anim — the sprite child — not the body. The CharacterBody2D (collision, position, physics) never moves; only the drawing leans 5px toward the victim and settles back. Faking motion on the visual layer means combat can never shove you into a tree.
Same rhythm as the swing: fast out (0.07, cubic-eased so it launches and lands soft), slower home (0.14). Note the pair: set_ease() only shapes a non-linear transition — on the default linear tween it does nothing, so it always travels with a set_trans().
The two tweens run in parallel with the blade frames because each is its own create_tween() — independent animations, one synchronized feel.

Part C — hit-stop: the frozen heartbeat

On a critical hit, attack() adds the heavyweight layer — you'll wire the full crit branch in below:

GDScript · player.gd
# A heartbeat of frozen time sells the crit.
func hit_stop():
    Engine.time_scale = 0.05
    await get_tree().create_timer(0.05, true, false, true).timeout
    Engine.time_scale = 1.0
await is new: it pauses this function at that line until the timer's timeout signal fires — while the rest of the game keeps running. No callback wiring, no connect: "wait here, then continue."
The fourth argument is the whole trick. create_timer(time, process_always, process_in_physics, ignore_time_scale) — that last true makes the timer tick in real time. Without it, the timer itself would run at 5% speed, and your 0.05-second heartbeat would freeze the game for a full second.
Why 0.05 and 0.05? Long enough for the brain to register a hitch, short enough to never read as lag. Hit-stop lives in the 30–100ms window; outside it, the magic dies in both directions.

Part D — the camera flinch

GDScript · player.gd
func shake_camera(strength: float):
    var t = create_tween()
    for i in 4:
        var off = Vector2(randf_range(-strength, strength), randf_range(-strength, strength))
        t.tween_property(camera, "offset", off, 0.04)
    t.tween_property(camera, "offset", Vector2.ZERO, 0.05)
Offset, not position. The camera's position belongs to its follow-the-player logic (Lesson 6); shaking the offset rattles the lens without ever fighting the follow. When the tween ends at Vector2.ZERO, the shake is guaranteed to leave no trace.
Four jolts, then home. A loop queues four random displacements at 0.04s each — chained, remember, not parallel — so the camera staggers drunkenly for ~0.16s and snaps back. strength is the only knob: crits pass 4.0.

Wire it up — the swing, assembled

Every layer exists; now they meet. swing() (Lesson 16's tick handler) becomes the conductor — and its dead-target reset now restores the rest texture instead of a rest angle:

GDScript · player.gd
func swing():
    if not is_instance_valid(target):
        swing_timer.stop()
        target = null
        sword.texture = SWING_FRAMES[0]   # settle back to the rest pose
        return
    face_toward(target.global_position)   # L29: square up
    swing_sword()                          # Part A: the frames + the swoosh
    lunge_toward(target.global_position)   # Part B: the lean
    if global_position.distance_to(target.global_position) <= attack_range:
        Sfx.play("swing", -4.0)
        attack(target)        # in range -> roll the table
    else:
        Sfx.play("miss", -10.0)

And the crit band of attack() (Lesson 22) gets its full celebration — sparks, flinch, the loud sound from Lesson 27, and the freeze:

GDScript · player.gd — inside attack()
elif roll < miss + dodge + parry + glancing + crit:
    var dmg = attack_damage * 2
    t.take_damage(dmg, true)
    gain_rage_dealing(dmg, true)
    spawn_sparks(t.global_position, Color(1.0, 0.85, 0.3), 10)   # gold burst (L28's helper)

The everyday hit, one band below, gets the quiet version: a small white burst — spawn_sparks(t.global_position, Color(1, 1, 1), 5) — and no shake, no freeze. Save the loud grammar for the rare outcome, or it stops being loud.

FEEL IT YOURSELF — BREAK THE TIMER

In hit_stop(), change the fourth argument to false and land a crit: the "frozen heartbeat" becomes a one-second stutter, because the timer is now counting frozen seconds. Put it back, then try Engine.time_scale = 0.4 with a 0.4s timer — congratulations, you've invented the slow-motion finisher. Revert when done (or don't; it's your game).
