A Death Worth Respawning From

Since Lesson 13, dying has meant "health reached zero, scene reloads" — a teleport, not an event. Today the body talks the whole way down: a red flash per bite, a heartbeat when you're low — and at zero, a sting, a slow fade, gold words, and a fresh dawn at camp.

TODAY

Take a bite: the screen flashes red and your HP bar drains instead of snapping. Drop to roughly a third (35%): the whole screen breathes a faint red heartbeat. Hit zero: the world stops, a sting plays, everything fades to near-black, "— Memory Eternal —" rises in gold… and 2.4 seconds later you wake at the campfire.

The big idea: failure is a state, not a teleport

Two ideas share this lesson, and they're really one idea. First: damage is a spectrum of states — grazed, hurting, nearly dead, dead — and each state should look and sound different, or the player learns nothing from being in it. Second: the moment of death needs a latch — one boolean, dying, that flips once and is checked everywhere. Without it, a corpse can keep swinging, a second bite can kill you twice, and the respawn timer can get scheduled twice. With it, death happens exactly once, with ceremony.

ColorRect

A Control that draws one flat color. Stretched over the whole screen inside the HUD's CanvasLayer, it becomes an overlay: red at 0 alpha = an invisible flash waiting to happen; near-black = a curtain.

latch (guard flag)

A boolean that flips one way during play and gates everything after it. dying is our second — the wolf has carried one since its own death tween, for the same reason.

set_physics_process(false)

Turns a node's _physics_process() off entirely. The dead can't walk: no input check even runs.

mouse_filter = Ignore

Full-screen Controls eat mouse clicks by default — set Mouse → Filter → Ignore on every overlay, or your click-targeting dies the moment the flash node exists.

Part A — the screen feels the bite

Two overlay nodes join the HUD (both ColorRect, both full-rect anchors, both Mouse Filter: Ignore):

▸ HUD (CanvasLayer) ├─ HurtFlash (ColorRect — red (0.78, 0.08, 0.06), alpha 0, full screen) └─ DeathScreen (ColorRect — near-black (0.02, 0.015, 0.01), alpha 0, hidden) └─ DeathLabel (Label — "— Memory Eternal —", pixel font, banner gold, centered, modulate alpha 0)
◈ ORDER IS DRAW ORDER

In a CanvasLayer, children draw top-to-bottom in tree order. Drag HurtFlash to the top of HUD's children — the wince renders under your unit frames, so the bars stay readable mid-flash. DeathScreen goes last — the curtain must fall over everything, frames and hint chips included.

Their handles join hud.gd's @onready block:

GDScript · hud.gd — with the other @onready vars
@onready var hurt_flash = $HurtFlash
@onready var death_dim = $DeathScreen
@onready var death_label = $DeathScreen/DeathLabel
The variable names the job, not the node: death_dim points at DeathScreen — in code we care about what it does (dims the world), and the rename is one more reason node-name string checks (Lesson 8's warning) are brittle.

The flash is two tween steps in hud.gd — sharp in, slow out, like a wince:

GDScript · hud.gd
func flash_hurt():
    var t = create_tween()
    t.tween_property(hurt_flash, "color:a", 0.22, 0.05)
    t.tween_property(hurt_flash, "color:a", 0.0, 0.4)

Over in player.gd, the latch variable joins the state block (next to has_sword):

GDScript · player.gd
var dying = false

And take_damage() — the function you built in Lesson 13 — now answers every hit with feedback before it acts on the consequences:

GDScript · player.gd
func take_damage(amount, from = null):
    if dying:
        return
    health -= amount
    if health < 0: health = 0
    var bt = create_tween()
    bt.tween_property(health_bar, "value", health, 0.25).set_trans(Tween.TRANS_CUBIC).set_ease(Tween.EASE_OUT)
    Sfx.play("hurt", -4.0)
    hud.flash_hurt()
    spawn_number(amount, Color(1.0, 0.36, 0.22))   # hot red-orange — reads on dirt and grass alike
    gain_rage_taking(amount)      # getting hit builds rage too
    if is_instance_valid(from):       # hit by an enemy -> engage it
        if not is_instance_valid(target):
            set_target(from)          # no target = retaliate attacker
        if swing_timer.is_stopped():
            swing_timer.start()
    if health == 0:
        die()
The latch guards the door. First line: if death is already in progress, the function refuses to run. A wolf mid-bite when you die can't hurt a corpse, re-trigger the flash, or — worst — schedule a second respawn.
The bar drains, never snaps. Tweening health_bar.value over 0.25s (cubic, eased — the pair from Lesson 30) turns "number changed" into "life leaving." Tiny cost, huge read.
Four feedback layers before any consequences — bar (the drain), sound (the bus), screen (the flash), world (the floating number) — then the rage, retaliation, and death checks you've had since the combat arc. Feedback first is a habit, not an accident: it's the part the player actually perceives.

Part B — the heartbeat near a third

Persistent states need persistent signals. The HUD's _process() — which already looks the player up every frame — gains a counter and one more call:

GDScript · hud.gd
var _pulse_t = 0.0

func _process(delta):
    var player = get_tree().get_first_node_in_group("player")
    if player == null:
        return
    _update_target_frame(player)        # toured later this arc
    _update_low_health_pulse(player, delta)
    _update_hints(player)               # next lesson's star

The pulse itself is four lines — note how it shares the HurtFlash node:

GDScript · hud.gd
# Soft red heartbeat overlay when health runs low.
func _update_low_health_pulse(player, delta):
    if player.dying:
        return
    if player.health > 0 and player.health <= player.max_health * 0.35:
        _pulse_t += delta * 5.0
        hurt_flash.color.a = maxf(hurt_flash.color.a, 0.06 + 0.05 * sin(_pulse_t))
sin() is the heartbeat. 0.06 + 0.05 · sin(t) breathes between 0.01 and 0.11 alpha, ~0.8 beats a second at delta * 5.0. Trig for rhythm, no timers, no animation file.
maxf() is the diplomacy. The pulse and the bite-flash share one node. Taking the maximum means a fresh 0.22 flash always wins over the 0.11 pulse — the pulse can never dim a wince in progress.
⚠ HISTORICAL DEBT: THIS WAS POLLING

This checkpoint rides the HUD's _process(), which asks the player's health every frame — exactly what Lesson 11 taught us to avoid ("events over polling"). The overhaul shipped it this way because the death pass needed to land. Lesson 35 pays the debt: the final HUD starts and stops the low-health pulse from health_changed instead of polling.

Part C — the latch flips: die()

GDScript · player.gd
func die():
    dying = true
    set_physics_process(false)
    foot_dust.emitting = false
    swing_timer.stop()
    Sfx.play("death")
    hud.show_death_screen()
    var t = create_tween()
    t.tween_property(anim, "modulate:a", 0.0, 0.9)
    t.parallel().tween_property(sword, "modulate:a", 0.0, 0.9)
    get_tree().create_timer(2.4).timeout.connect(get_tree().reload_current_scene)
Order matters: flip the latch, silence the body — set_physics_process(false), and since every input check this player has lives inside _physics_process(), the dead read no input — stop the emitters and timers, then start the ceremony. Logic off, presentation on.
The sting is out of the reload's reach — Sfx.play("death") parents the sound to the bus (Lesson 27), so even a reload landing mid-note couldn't cut it short. (Here it never comes to that: the 1.6s sting finishes with time to spare before the 2.4s reload — but the guarantee is why the bus exists.)
The respawn is one connect: a 2.4-second one-shot timer wired straight to reload_current_scene — the same Lesson 8 signal-to-function wire, pointed at the engine itself. The forest regenerates (same seed, same world — Lesson 26), health is full, the sword waits on its pedestal again.

Part D — the curtain

GDScript · hud.gd
func show_death_screen():
    death_dim.visible = true
    var t = create_tween()
    t.tween_property(death_dim, "color:a", 0.82, 1.1)
    t.parallel().tween_property(death_label, "modulate:a", 1.0, 1.4)
    t.parallel().tween_property(death_label, "position:y", death_label.position.y - 10, 1.4).set_trans(Tween.TRANS_CUBIC).set_ease(Tween.EASE_OUT)
0.82, not 1.0. The world stays faintly visible under the curtain — you died somewhere, and the dim forest behind the words quietly says so. Full black would cut the thread to the place you're about to wake up in.
The label out-lives the dim: dim finishes at 1.1s, the words keep rising and brightening until 1.4s. Two layers ending at different times is what makes it read as staged rather than switched.
A confession: this exact line originally shipped with set_ease() and no set_trans() — Lesson 30's no-op. The label rose in a straight line until today and nobody noticed, which tells you how subtle the bug is. The rule again: set_ease always travels with set_trans.
FEEL IT YOURSELF — TUNE THE CEREMONY

Set the dim target to 1.0 and die again: total black — final, but the world is gone and the respawn feels like a level change. Now set the respawn timer to 0.5: whiplash — the words barely land before dawn. The shipped numbers (0.82, 2.4) are one answer to "how long should a death be?"; now you know what question they're answering. Revert when done.
